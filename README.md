# 方舟培养参谋 · Arknights Training Advisor

> 练谁 · 缺什么 · 去哪刷 —— 开源的明日方舟培养规划工具

**在线使用（GitHub Pages）：<https://1000zyq1000.github.io/arkn-advisor/>**

[![CI](https://github.com/1000zyq1000/arkn-advisor/actions/workflows/ci.yml/badge.svg)](https://github.com/1000zyq1000/arkn-advisor/actions/workflows/ci.yml)

基于**你自己的 box**（干员练度）与**材料库存**，回答三个问题：

1. **培养推荐** —— 结合目标玩法（主线推图 / 高难合约 / 肉鸽 / 保全派驻）或**目标关卡**（关卡机制 × 干员亲和），从「你还没练的干员」中给出**透明的优先级评分与理由**，而不是一份与你的账号无关的通用强度榜；
2. **养成规划** —— 选定目标干员与目标阶段，计算材料总需求，扣除库存后给出**合成建议与缺口清单**；
3. **刷图规划** —— 按「每单位理智期望产出」推荐刷图关卡与次数，汇总预计总理智。

纯前端、纯本地计算，**不上传任何数据**；box 与库存仅保存在浏览器 localStorage。

## 使用流程

1. **导入**：在「① 导入」页录入干员 box（粘贴 JSON / 手动编辑 / 一键载入示例）与材料库存；
2. **推荐**：在「② 培养推荐」选择目标玩法，生成 Top 10 优先级清单（附评分依据）；
3. **规划**：在「③ 养成规划」勾选目标干员、选择目标阶段（精一/精二），得到材料缺口、合成建议与刷图清单。

## 评分与规划语义（透明度声明）

**推荐评分**（`src/lib/recommend.ts`）：

```
score = valueScore ÷ costFactor
valueScore = 稀有度基数 × 职业权重(按玩法预设) × (0.7 + Σ 标签权重×标签稀缺度)
costFactor = 已精一未达高练度线 ? 0.65 : 1.0
```

- 「高练度」定义：精二，或精一且等级 ≥ 45；
- 已高练度的干员不会进入推荐；
- 全部权重集中在 `src/lib/goals.ts`，欢迎通过 PR 调整。

**刷图规划**（`src/lib/planner.ts`）v0.3 语义：

- 需求按材料等级升序处理，库存优先抵扣；
- 对每个缺口比较两条路线的理智成本：**直接刷取** vs **合成获得**（原料缺口递归求解，可多级展开）；
- 择优执行，同价优先直接刷取；路线估算基于当前库存快照（贪心近似，非全局最优）；
- 为合成供料而刷取/合成的行会标注“为某材料合成供料”；
- 未建模：等级经验/龙门币的精确定价、技能专精与模组消耗、合成站效率加成、跨需求的全局最优分配。

以上均为有意的 v1 裁剪，路线图见下。

## 架构

```
src/
├── lib/                 # 纯逻辑层（全部有单元测试，不依赖 UI）
│   ├── types.ts         # 领域模型
│   ├── data.ts          # 数据集加载（当前：内置样例）
│   ├── demand.ts        # 养成需求计算
│   ├── planner.ts       # 缺口 / 合成 / 刷图规划
│   ├── recommend.ts     # 推荐评分引擎
│   ├── goals.ts         # 玩法预设权重（欢迎 PR）
│   └── import/          # 导入适配器（generic 宽容解析；maa 严格解析，格式已核实）
├── data/                # 数据集（见 data/README.md 的数据约定）
├── components/          # UI 组件（导入 / 推荐 / 规划 / 说明）
└── styles/global.css    # 设计系统（无 CSS 框架依赖）
tests/                   # Vitest 单元测试
```

核心逻辑与 UI、数据来源完全解耦：替换 `src/lib/data.ts` 的加载实现即可接入真实数据源，UI 与算法不感知。
